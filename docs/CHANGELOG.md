- 2026-11-02 — **adb over USB works.** Research first: upstream `Damir00109/Redmi10c` already ships a working FunctionFS+`adbd` stack on mainline 7.1.5, and the archived postmarketOS `xiaomi-fog` port had USB RNDIS on downstream 4.19 — both confirm the USB hardware path. Root cause of our "never enumerates" was two faults: (1) our `qcom,dwc3` glue claimed USB GCC clocks/GDSC/BCR while upstream's thin DT leaves them in `protected-clocks` (the femto driver + initramfs drive QSCRATCH/GDSC/AHB2PHY), and (2) `GHWPARAMS0.AWIDTH=64` made dwc3 take a 64-bit DMA mask, so the event ring landed at `0x1_022fc000`, which this USB master never wrote — every event read back zero (`unknown endpoint event 0`, 111/boot), ep0 never completed, host never enumerated. `snps,force-32bit-dma` moves the ring to `0x43800000`; storm 111 → 0. Adopted the upstream ADB gadget + Debian `adbd` (trixie debs staged by `tools/fetch-adbd-debs.sh`, host key installed by `make rootfs`); disabled the old ACM unit/getty that killed adbd via `Conflicts`, and fixed the boot-report exec bit. — files: patches/fog-adb-usb.patch, Makefile, build/overlay/{usr/local/sbin/usb-adb-gadget.sh,etc/systemd/system/{adbd,usb-adb-gadget}.service,usr/local/sbin/boot-report.sh,etc/systemd/system/getty@ttyGS0.service.d/override.conf}, build/install-overlay.sh, tools/{fetch-adbd-debs.sh,testboot-loop.sh}, RUNBOOK.md, README.md, UPSTREAM.md — verified: `adb devices` → `rain device`, `adb shell` root on 7.1.5, `udc state configured`, `endpoint-event spam 0`, event ring `0x43800000`; unattended `make test SKIP_CUST=1` flash→boot→adb→self-reboot→PBRP pull.

- 2026-11-01 — Made the autonomous test loop actually work and used it to cut the USB problem in half. Loop fixes: `--set-active` does **not** reboot on this ABL (so the script must reboot itself), a return to fastboot only counts after fastboot has gone away once (otherwise the still-present bootloader reads as success), the slot check must compare `current-slot` and not only the retry counter, and stale report files must be deleted before the PBRP pull (the image ships an old report from build time). USB findings: EUD is *not* hijacking the port (0x1611014 and 0x1612000 both read 0); `DWC3_DCTL_RUN_STOP` is bit 31, so `DCTL=0x80f00000` means running (the previous "controller halted" reading was a wrong bit); `usb-force.py`'s DCTL stop/start was restarting the controller behind dwc3's back and corrupting the event ring — removing it cut the `unknown endpoint event 0` storm from 82 to 21 per boot; the sm6115 "thin" board crash-loops before userspace and has no log path, so it is abandoned as a test vehicle — files: tools/testboot-loop.sh, build/overlay/usr/local/sbin/{boot-report.sh,usb-gadget.sh,usb-force.py}, RUNBOOK.md — verified: three unattended flash→boot→pull cycles, registers read on-device each time

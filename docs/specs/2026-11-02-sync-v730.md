# 2026-11-02 — sync to upstream `v7.3.0` (kernel v7.3 + Ubuntu 26.04 rootfs)

Status: in progress. Issue: https://github.com/xinkev/fog-linux/issues/7

## Goal

Move the port from "base `main` @ 2026-09-07, kernel 7.1.5, hand-built Ubuntu
24.04 rootfs" to upstream's current `origin/v7.3.0` tree, while keeping the
parts that are proven on *our* `fog` unit:

- `qcom,board-id = <0x40022>` in `sm6225-xiaomi-fog.dts` (upstream still says
  `0x60022`; `make verify` must keep rejecting that).
- The proven USB HS-PHY wiring (PM6125 L4 0.88 V as `vdda-pll`, L12 pinned
  1.8 V, L15 3.232 V, no `cfg_ahb`, `param-override-seq`) — fall back to it
  only if v7.3's own USB setup fails on our unit.
- Our flash/test/report layer: `tools/testboot-loop.sh`, `tools/doctor.sh`,
  `tools/verify-image.sh`, `tools/adb-status.sh`, boot report into `cust`.

Everything else (kernel, config, initramfs, overlay, systemd units, firmware
staging) comes from `v7.3.0` unmodified where possible.

## Non-goals

- Not fixing audio/modem/GPS/sensors ourselves — v7.3.0 already has them; we
  only verify they come up, and only debug what breaks on `fog` EEA.
- Not touching slot A / Android, not re-locking, not changing `vbmeta_a`.
- Not adopting upstream's firmware blobs as "ours": calibration data (Wi-Fi
  BDF, BT NVM, sensors) is per-device; phone-sourced blobs win where they
  differ.
- Not upstreaming our board-id/USB diffs in this task.

## Why v7.3.0 and not another tree

Checked 2026-11-02: no mainline `sm6225*.dts` in torvalds/master; pmOS/Nura
`xiaomi-fog` is archived on a 6.1 fork dead since 2024; lk2nd has no SM6225
DTS; Android device trees are reference-only. Damir's repo is the only
maintained mainline tree, and its `v7.3.0` is the newest branch (2026-10-27).

## Acceptance

1. `make image` produces `boot-linux.img` with `board-id 0x40022` and a DTB
   that boots on our unit (RAM boot first).
2. Userspace reaches `systemd` and `adb devices` shows the device; `adb
   shell` is root.
3. Framebuffer/DRM console and touch work on the device.
4. `make test` still does flash → boot → adb check → self-reboot → pull logs
   with the new paths.
5. `make rootfs` builds a flashable `cust` image (Ubuntu 26.04 + overlay).
6. Wi-Fi/BT either work with upstream blobs, or the gap is documented with
   the exact missing/incorrect blob for `fog` EEA.

## Risks

| Risk | Mitigation |
|---|---|
| v7.3 fog DTS uses `vdda-pll = l12` + `cfg_ahb`, which our unit rejected in 7.1.5 | First boot v7.3 as-is; if UDC never attaches, apply our proven `usb_hsphy` block (kept in this repo's patch history) |
| Upstream firmware release is calibrated on `rain` | Compare against `vendor.firmware_mnt` from our unit; keep our BDF/BT NVM if Wi-Fi/BT misbehave |
| Rootfs build script assumes Ubuntu host + `sudo` + loop mounts | Run in a privileged arm64 container (host is M1, native arm64; no qemu) |
| Ubuntu 26.04 needs more than the 2 GiB `cust` | Script uses 1800 MB image; verify after `make rootfs`, grow later (issue #4) |
| Kernel v7.3 patch may not apply / may OOM the 3 GB unit | Build first, RAM-boot, watch `pstore`/report; roll back to current image which stays untouched |

## Rollback

Current tested images stay in `Redmi10c-base/out/ubuntu-dualboot/`
(`boot-linux.img`, `linux_rootfs.sparse.img`, `vbmeta_b.img`). Reflashing
them restores 7.1.5 + Ubuntu 24.04. Slot A is never written.
